## Outcome and scope

- Implement the full extensible nutrient catalog in spec §7, with canonical units and SDK-verified HealthKit mappings only.

- Preserve null vs explicit zero, confidence, evidence source, bounds and user approval; support app-only unsupported nutrients.

- Implement per-nutrient off/confirmed_only/confirmed_plus_approved_estimates policy and explicit salt-vs-sodium conversion.

- Pin sodium/potassium in nutrient views with known-data coverage; aggregate decimal-safe values and round only for display.

## Acceptance criteria

- [ ] 2.4 g sodium normalizes to 2400 mg; unknown potassium stays unknown and creates no Health sample.

- [ ] Approved estimates remain labeled estimates and write only when policy allows.

- [ ] Missing fields and explicit zero remain distinct in storage, UI and exports.

## Validation and evidence

- Unit/range/conversion and precision tests; full registry mapping review against current SDK. Covers T-09/T-10/T-15.

## Boundaries

Implement only this issue; do not start later phases or optional enhancements.
