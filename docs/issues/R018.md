## Outcome and scope

- Implement draft/create/read/patch/soft-delete meal APIs with authenticated ownership and versioned validation.

- Require idempotency keys for mutations and expected revisions for conflicting edits; persist immutable before/after audit history.

- Commit app-owned desired Health state/outbox atomically with ledger revisions; preserve deletion identity and exclude never_legacy rows.

- Expose history and distinct app_saved/health_sync state; protect Health acknowledgment with a bound iOS device credential.

## Acceptance criteria

- [ ] Repeated submissions yield one logical mutation; stale revisions produce actionable conflicts.

- [ ] Transaction failure cannot leave a changed meal without its required outbox/audit record.

- [ ] Tombstones retain enough identity to remove old owned Health samples; legacy edits never enqueue writes.

## Validation and evidence

- Transaction rollback, request replay, stale write conflicts, soft-delete history, legacy no-outbox and unauthorized Health ack tests.

## Boundaries

Implement only this issue; do not start later phases or optional enhancements.
