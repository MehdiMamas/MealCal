# Gate release on full Cal AI parity and no missing daily workflows

<!-- mealcal-plan:P03 -->

**Roadmap:** [#37](https://github.com/MehdiMamas/MealCal/issues/37)

## Goal

The owner can replace paid Cal AI 26.40.0 on iPhone without losing everyday features or familiar workflows, while gaining the original spec's additions. Read [the scope update](https://github.com/MehdiMamas/MealCal/blob/main/docs/CAL-AI-PARITY.md). This gate supplements Q01 (#36) and T-01–T-20.

## Scope

- Depends on completed P01/P02 inventories and all required implementation issues discovered by them. Review the matrix whenever the pinned baseline changes; do not silently chase a different release.
- Repeat identical daily tasks on reference Cal AI and MealCal with synthetic/redacted comparable data. Measure steps, outcomes, visual differences, latency and error recovery.
- Validate every observed baseline feature, including settings/paid paths and relevant edge states. Keep unsupported, blocked, failed and unobserved separate from passed.
- Run at least one week of realistic private daily use and record every missing capability or extra-friction finding as an issue.
- Require owner review of any proposed omission or intentional UI/UX difference. Preserve safe HealthKit ownership, truthful sync, privacy and uncertainty behavior.
- Evaluate AI outcome quality separately from interface similarity; do not promise identical proprietary model outputs without evidence.

## Acceptance criteria

- [ ] Every verified baseline matrix row has passing feature, interaction and applicable visual evidence.
- [ ] No unresolved required workflow gap or unexplained regression remains.
- [ ] Owner-approved differences are documented; unreviewed differences do not count as accepted.
- [ ] Original additions and HealthKit/legacy-safety acceptance pass independently.
- [ ] Q01's release evidence links this gate; neither the old optional labels nor passing original tests alone can authorize a parity-complete claim.

## Validation

Use a pinned device/version/account context, dated evidence and a full scenario matrix. Public-source research, a simulator-only run or a zero-test screen comparison cannot satisfy real-device daily-use acceptance. No implementation is requested in the current planning task.
