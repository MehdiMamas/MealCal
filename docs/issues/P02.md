# Specify Cal AI screen-by-screen UI and interaction parity

<!-- mealcal-plan:P02 -->

**Roadmap:** [#37](https://github.com/MehdiMamas/MealCal/issues/37)

## Goal

Make the replacement feel familiar to a paid Cal AI 26.40.0 iPhone user. Match observed navigation, layout and interaction details as closely as possible, then integrate the requested additions. Read [the scope update](https://github.com/MehdiMamas/MealCal/blob/main/docs/CAL-AI-PARITY.md).

## Scope

- Work with P01's feature audit; map every screen, tab, sheet, modal, gesture and user journey, including paid/account-only surfaces.
- Capture typography, spacing, colors, cards, icons, charts, animations, haptics, keyboard, device sizes and accessibility behavior using sanitized references.
- Cover loading/empty/error/permission-denied/offline states and save/edit/delete/cancel/back behavior, not only ideal screenshots.
- Record actual task sequences, tap counts and visible results. A capability hidden behind additional steps or external JSON copy/paste is not automatically equivalent UX.
- Create original implementation/assets; preserve MealCal identity. Keep private recordings outside the public repository and commit only sanitized descriptions.
- Design additions so they retain familiar baseline actions. Adapt desktop web deliberately while keeping iPhone the comparison reference.

## Acceptance criteria

- [ ] A versioned screen/state inventory and navigation graph map to the feature matrix.
- [ ] Each baseline workflow has interaction acceptance and suitable reference views.
- [ ] Intentional differences and unavailable observations are explicit and receive owner review.
- [ ] A side-by-side visual/interaction comparison method is documented for matching iPhone dimensions and representative states.
- [ ] Client design cannot be declared complete with unexamined baseline surfaces.

## Validation

Walk the reference app through all documented paths; review references and state coverage before implementing UI. Use screenshot comparison and actual task execution later; static visual similarity alone cannot pass behavioral parity. Current access is insufficient to certify the inventory.

**Depends on:** Feature discovery in [P01](https://github.com/MehdiMamas/MealCal/issues/38); work on reference capture can overlap.
