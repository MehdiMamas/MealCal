## Outcome and scope

- Configure Supabase Auth for one authorized user, MFA, secure sessions, recovery and disabled public signup.

- Document private Vercel web access and direct development/Ad Hoc or TestFlight install.

- Protect server routes and keep service-role credentials out of clients; secure native tokens in Keychain.

## Acceptance criteria

- [ ] Authorized owner can sign in on desktop web and iPhone; anonymous and second-user access is denied.

- [ ] Session revocation/recovery works and deployment remains private.

- [ ] Native distribution limitations, including any TestFlight expiry, are documented.

## Validation and evidence

- Auth and access integration tests, second-user/anonymous negative tests, recovery/revocation and private deployment smoke checks.

## Boundaries

Implement only this issue; do not start later phases or optional enhancements.
